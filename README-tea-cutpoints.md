# 茶样含水率换档点分析（tea_cutpoints）

按**送检顺序**对茶样批次做最优分段，找出含水率换档点，并**精确**给出并列最优切法总数与各切点出现次数。单页面发起研究，从“待算”到显示切点次数；并发改样/调序时排队冻结同一时点的输入，冻结输入可重跑且切点计数保持一致。

## 模型与算法

- **输入**：送检顺序固定的 n 个批次；第 i 批 m_i 份含水率读数（1 ≤ m_i ≤ 40）；每刀罚分 λ ≥ 0。
- **经验分位曲线**：每批 Q_i(p) = 第 ⌈m_i·p⌉ 个次序值（p∈(0,1]），阶梯函数。
- **段代表**：段内各批曲线的**逐点中位数**（偶数批取低中位数；绝对差之和对两中值间任意取法不变，代价无歧义）。
- **段代价**：Σ_i ∫₀¹ |Q_i(p) − M(p)| dp，**各批等权**（不按份数加权）。
- **总代价**：各段代价之和 + λ × 刀数（刀数 = 段数 − 1）；**每段至少 3 批**。
- **精确比较**：读数缩放为 10⁶ 整数；所有拐点都是 k/m_i（m_i ≤ 40），取公分母
  DEN = lcm(1..40) = 5342931457063200 后段代价 = 整数分子 / DEN。比较与并列判定全部在
  （大）整数上进行，无浮点误差。
- **计数不枚举**：DP 求最小总代价；前向/后向两遍计数得并列最优切法总数 g[n]；
  切点 i 的出现次数 = g[i]·h[i]，当且仅当 f[i] + λ + sf[i] = 全局最优（经过 i 的最优
  前后缀拼出全局最优）。不逐套枚举。

## 运行

```bash
# 方式一：零依赖（纯 Python 回退引擎，结果一致、稍慢）
python3 -m tea_cutpoints --port 8000

# 方式二：venv（numpy 加速，80批×40份约 0.25s）
.venv/bin/python -m tea_cutpoints --port 8000
```

打开 http://127.0.0.1:8000/ ：新建研究（可点“大例80批×40份”）→ 编辑/调序批次、设罚分 →
**发起计算（冻结当前输入）** → 运行记录从“待算/计算中”变为“完成” → 查看并列最优切法总数、
各切点出现次数（条形图 + 表格）→ 可“冻结重跑”验证切点计数一致。

## 冻结与重跑语义

- 所有改动（编辑读数、增删批次、调序、调罚分）与“发起计算”共用一把锁；每次运行在
  入队瞬间**原子冻结**完整快照（批次顺序 + 全部读数 + 罚分），并记录其 SHA256。
- 计算任务进入单 worker 的 FIFO 队列逐个执行；运行期间的改动只影响“当前状态”，
  不改写已冻结快照。
- 引擎确定性：同一冻结输入重跑，切点计数必然一致；`POST .../runs/{id}/rerun`
  用冻结输入重算并显式给出 `consistent` 复核标记。

## API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/studies` / `/api/studies/{id}` | 列表 / 详情（含运行摘要） |
| POST | `/api/studies` | 创建 `{name, penalty, batches:[[读数...]...]}` |
| PUT | `/api/studies/{id}` | 改名 / 调罚分 |
| PUT/POST | `/api/studies/{id}/batches` | 整体替换 / 追加批次 |
| PUT/DELETE | `/api/studies/{id}/batches/{idx}` | 改读数 / 删批次 |
| POST | `/api/studies/{id}/move` | 调序 `{from, to}` |
| POST | `/api/studies/{id}/runs` | 冻结当前输入并排队 |
| GET | `/api/studies/{id}/runs/{rid}` | 状态与结果（切点次数） |
| POST | `/api/studies/{id}/runs/{rid}/rerun` | 用冻结输入重跑并复核一致性 |

结果中 `num_optimal` 与 `cut_counts[].count` 以字符串承载（可能超出 JS 安全整数）。

## 测试

```bash
.venv/bin/python -m pytest tests/ -q        # numpy 引擎
python3 -m unittest discover -s tests -t .  # 纯 Python 回退（零依赖）
```

- `tests/test_core.py`：**小例穷举核对**（220 组随机小例 + 60 组小数读数，与独立
  Fraction 穷举 oracle 逐点比对总代价、并列数、切点计数；覆盖样本量不等与构造并列）。
- `tests/test_api.py`：页面链路（待算→完成→切点次数）、冻结重跑一致、**并发改样/调序**
  时快照冻结与队列串行、参数校验。
- `tests/test_perf.py`：**80 批 × 40 份 < 30 秒**（numpy 约 0.25s，纯 Python 约 0.9s）；
  不等份数与对抗性份数（31..40 循环）同样 < 30 秒；numpy 与纯 Python 逐段结果一致。

## 已知边界

- 数据存于内存，重启即清空（小型研究工具定位）。
- 读数按 10⁻⁶ 微单位取整（ROUND_HALF_UP，确定性）；罚分同单位。
- 每批份数上限 40、每段至少 3 批为硬约束；不足三批拒绝创建与计算。
